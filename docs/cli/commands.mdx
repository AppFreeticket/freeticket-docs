Each command calls one [B2B API](/reference/v1) operation and needs the same minimum role in the target workspace. This page matches `@freeticket/cli` 0.11. Run `ft <command> --help` for the exact flags of your installed version.

## Shared flags

| Flag | Applies to | Purpose |
| --- | --- | --- |
| `--json` | All commands | Raw JSON on stdout. On lists, the `data` array only. |
| `--workspace <id>` | All commands | Target one workspace. See [Workspaces](/cli/workspaces). |
| `--account <name>` | Most commands | Use one stored account. See [Several accounts](/cli/login#several-accounts). |
| `--limit <n>` | Lists | Page size, 1 to 100 (default 20) |
| `--cursor <id>` | Lists | Continue from a previous page (single workspace only) |
| `--all` | Lists | Fetch every page |
| `--raw` | Lists | JSON with the `{ data, page }` envelope, including `page.nextCursor` |
| `--columns <a,b,c>` | Lists | Choose the columns to show |
| `--full` | Lists | Show every field |
| `--csv` | Lists and reports | CSV output |
| `--data <json>` | Writes | Request body: inline JSON or `@file.json` |
| `--yes` | Deletes and cancels | Skip the confirmation prompt |

Write commands take the same JSON body the API does. The [API reference](/reference/v1) documents every field.

## Session and workspaces

| Command | Purpose |
| --- | --- |
| `ft signup --email <email> --name <name>` | Create an account. `--workspace-name` also creates its first workspace. |
| `ft login` | Browser login, adds an account. `--key <key>` for CI, `--account <name>` to name it. See [Log in](/cli/login). |
| `ft whoami` | Your user and workspaces, for every stored account |
| `ft config` | Show the active configuration, with credentials masked |
| `ft logout` | Remove the pinned or only account. `--account <name>`, `--all`. |
| `ft account list` · `use <name>` · `clear` · `remove <name>` | List, pin, unpin and remove stored accounts |
| `ft workspace list` · `use <id\|slug>` · `clear` · `show` | List, pin, unpin and show workspaces |
| `ft workspace create --name <name> --slug <slug>` | Create your own workspace. You become its `ADMIN`. |

## Events and dates

| Command | Role | Purpose |
| --- | --- | --- |
| `ft events list` | VIEWER | Filters: `--q <text>`, `--status <DRAFT\|PUBLISHED\|SOLD_OUT\|CANCELLED\|COMPLETED>`, `--with-total` |
| `ft events get <id>` | VIEWER | One event |
| `ft events create --data <json>` | ADMIN | Create an event with its dates |
| `ft events update <id> --data <json>` | ADMIN | Update an event |
| `ft events publish <id>` | ADMIN | Publish. Needs at least one future date. |
| `ft events cancel <id>` | ADMIN | Cancel the event and all its dates. Keeps sales and tickets, refunds nothing. Asks first. |
| `ft events delete <id>` | ADMIN | Delete an event (soft delete). Fails with `EVENT_HAS_SALES` if it has paid sales: cancel it instead. |
| `ft event-dates list <eventId>` | VIEWER | Dates of an event |
| `ft event-dates create <eventId> --data <json>` | ADMIN | Add a date |
| `ft event-dates update <eventId> <dateId> --data <json>` | ADMIN | Update a date |
| `ft event-dates delete <eventId> <dateId>` | ADMIN | Delete a date |

```bash
ft events create --data '{
  "name": "Concierto de prueba",
  "slug": "concierto-de-prueba",
  "dates": [{ "startsAt": "2026-12-12T01:00:00Z", "timezone": "America/Bogota" }]
}'
```

## Sales

| Command | Role | Purpose |
| --- | --- | --- |
| `ft sales list` | VIEWER | Filters: `--status`, `--channel`, `--event`, `--event-date`, `--reference`, `--buyer`, `--from`, `--to` |
| `ft sales get <id>` | STAFF | One sale with its items |
| `ft sales tickets <id>` | STAFF | The individual tickets of a sale |
| `ft sales attempts <id>` | STAFF | Payment attempt history: why a sale didn't go through |
| `ft sales create --data <json>` | ADMIN | Record a comp or offline sale, created as `CONFIRMED` |
| `ft sales cancel <id>` | ADMIN | Cancel and release the stock |
| `ft sales refund <id>` | ADMIN | Refund the sale, or some of its tickets |

Sale statuses are `PENDING`, `CONFIRMED`, `ABANDONED`, `CANCELLED` and `REFUNDED`. Channels are `WEB`, `MOBILE`, `POS` and `ADMIN`.

`cancel` and `refund` take an optional `--data` body. To refund only some tickets, pass the item ids from `ft sales tickets`, and add `"block_seats": true` to keep refunded numbered seats off sale:

```bash
ft sales refund <sale-id> --data '{"items":["<item-id>"]}'
```

When the API answers `409` because the payment state needs a human decision, it explains what to check. You can then repeat the command with `--data '{"acknowledge_open_payment":true}'` (cancel) or `--data '{"acknowledge_manual":true}'` (refund). Tickets already checked in can't be refunded.

:::warning
A refund marks the sale as refunded, but the money only goes back automatically for some payment methods. For the others, return the money from your payment provider's dashboard. The [refund operation](/reference/v1) describes each case.
:::

## Tickets (door operations)

Tickets are addressed by their **ticket code**, the QR payload.

| Command | Role | Purpose |
| --- | --- | --- |
| `ft tickets access <code>` | STAFF | Check whether a ticket is valid, without admitting it |
| `ft tickets checkin <code>` | STAFF | Admit the ticket. Idempotent: a second scan doesn't admit it twice. |
| `ft tickets resend <code>` | ADMIN | Resend the ticket email to the buyer |
| `ft tickets reassign <code> --data <json>` | ADMIN | Move a sold ticket to another date and/or ticket type, for a postponement |

```bash
ft tickets reassign <ticket-code> --data '{"eventDateId":"<new-date-id>"}'
```

The ticket keeps its code and original price, and the buyer isn't notified: run `ft tickets resend <code>` afterwards. On a numbered-seating date, `seatLabel` is required.

## Reports and exports

| Command | Role | Purpose |
| --- | --- | --- |
| `ft reports summary` | VIEWER | KPIs. `--period 7d\|30d\|90d\|1y` (default `30d`) |
| `ft reports by-event` | VIEWER | Revenue and tickets by event. `--from`, `--to`, `--status` |
| `ft reports timeseries --interval <day\|week\|month>` | VIEWER | Confirmed sales over time. `--from`, `--to`, `--event` |
| `ft reports inventory` | VIEWER | Capacity, sold, reserved and available. `--event`, `--event-date`, `--from`, `--to`, `--include-drafts`, `--group-by <ticketType\|date\|event>` |
| `ft reports financials` | ADMIN | Per-date financial statement: gross, costs and net to settle. `--event`, `--past` |
| `ft reports reconciliation --from <date> --to <date>` | ADMIN | Payment ↔ sale ↔ invoice reconciliation. `--match`, `--provider`, `--page`, `--page-size` |
| `ft reports export buyers` | ADMIN | One row per sale. `--event`, `--event-date`, `--from`, `--to`, `--status` |
| `ft reports export attendees` | ADMIN | One row per ticket, with the same filters |
| `ft reports export subscribers` | ADMIN | Membership subscribers |
| `ft reports export reconciliation --from <date> --to <date>` | ADMIN | Reconciliation export |

Exports return up to 5,000 rows. Add `--csv` for spreadsheets.
