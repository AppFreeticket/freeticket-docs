A **workspace** is one organizer, venue or artist account. By default **nothing is pinned**:

- `list` commands and the row-based reports (`by-event`, `timeseries`, `inventory`, `financials`, `reconciliation`) read **every workspace you can access**, across every [stored account](/cli/login#several-accounts). Each row gets `workspaceId` and `workspaceName`, plus `account` when more than one account is involved. A workspace two accounts both reach is read once.
- `reports summary` returns KPIs for one workspace, because KPIs can't be added up across workspaces.
- Other commands (get, create, update…) run against your account's default workspace.

```bash
ft workspace list
```

```text
┌────────┬──────┬────────────┬────────────┬───────┬────────┐
│ active │ id   │ name       │ slug       │ role  │ access │
├────────┼──────┼────────────┼────────────┼───────┼────────┤
│ *      │ …    │ My Venue   │ my-venue   │ ADMIN │ full   │
│        │ …    │ Tour 2026  │ tour-2026  │ STAFF │ full   │
└────────┴──────┴────────────┴────────────┴───────┴────────┘
```

`role` is your role **in that workspace**. `access` is `full`, the list of sections you can use, or `revoked`. With several accounts stored, the list covers all of them. Narrow it with `--account <name>`.

## Pin a workspace

```bash
ft workspace use my-venue      # by slug or id
ft workspace show              # what is active now
ft workspace clear             # unpin: read all workspaces again
```

Pinning stores the workspace in `~/.freeticket/config.json` and sends it as the `X-Workspace-Id` header on every request. `ft workspace use` finds the workspace in whichever stored account reaches it and pins both.

## Create a workspace

```bash
ft workspace create --name "My Venue" --slug my-venue
```

This calls `POST /workspaces`. You become the new workspace's `ADMIN`. The slug takes lowercase letters, digits and dashes.

## Override per command

Every command takes `--workspace <id>`:

```bash
ft events list --workspace <workspace-id>
ft events create --workspace <workspace-id> --data @event.json
```

## Pagination across workspaces

`--cursor` only works with a single workspace, because a cursor from one workspace means nothing in another. When you read several:

- `--limit` is split between the workspaces.
- `--all` walks every page of every workspace.
- If one workspace or account fails, its error goes to stderr and the others still return. If all of them fail, the command exits with `1`.

To page manually, pin a workspace first (`--workspace` or `ft workspace use`).
