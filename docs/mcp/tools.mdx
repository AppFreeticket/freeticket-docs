The hosted server exposes up to 200 tools: 6 public tools, 177 workspace tools and 17 buyer tools. Which ones a connection lists depends on its [credentials](/mcp/authentication). Each tool calls one API operation, with the same roles, validation and errors as the [B2B API reference](/reference/v1). Tools marked **destructive** ask for confirmation in clients that support it.

A read-only connection (OAuth scope `read`) lists only the read tools. Write tools don't appear at all, so reconnect with write access if one is missing.

## Public (no credential)

Available on `/mcp` with or without sign-in, and on `/mcp/public`.

| Tool | Does |
| --- | --- |
| `public_events_list` | Search the catalog of published events |
| `public_events_get` | Event detail by slug |
| `public_events_availability` | Live stock and buyer prices per date and ticket type. Check it before creating an order. |
| `public_orders_create` | Create an order and return the payment link for the buyer |
| `public_orders_get` | Order status (`pending`, `paid`, `expired`, `cancelled`), plus tickets once paid |
| `public_tickets_resend` | Resend the ticket email to the buyer's original address |

Public ordering covers general admission tickets that are not members-only.

## Platform staff

A separate set of `admin_*` tools manages the platform itself. They are only available on a local stdio server started with `FT_ADMIN_SESSION`. The hosted server never exposes them.

## Output and errors

- Responses are compact JSON, capped at 25,000 characters. When a list doesn't fit, it is cut by whole items and carries `truncated: { shown, total, field, hint }`, with `page.nextCursor` set to `null`. To continue without skipping rows, repeat the same call with the same `cursor` and `limit` set to `shown`.
- `sales_list`, `sales_tickets`, `sales_attempts`, `reports_export_buyers` and `reports_export_attendees` return trimmed rows by default. Pass `verbose: true` for the full row.
- `limit` is a number from 1 to 100.
- Errors keep the API's `error.code` and add `status`, `retryable`, a `hint` with the next step and, after a `429`, `retryAfterSeconds`.

## Rendered results

In clients that support the MCP Apps extension, list and report tools render as a table or KPI tiles instead of raw JSON. The view is self-contained and makes no network requests. Other clients receive the same data as text.

## Global mode

Unless the connection is pinned to one workspace, list and row-based report tools read **every workspace you can access**. Their `workspace` argument narrows that:

- Leave it out, or pass `"all"`: every workspace you can access.
- `["id1", "id2"]`: only those workspaces. An id you can't reach comes back as an error for that id instead of being dropped silently.

Rows are tagged with `workspaceId` and `workspaceName`. Aggregated results carry no pagination cursor, so name one workspace to page deep. A workspace that fails is reported while the others still return. `reports_summary` returns KPIs for one workspace only, because KPIs can't be added up across workspaces. Writes always act on one workspace.
