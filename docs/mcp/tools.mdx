The hosted server exposes 94 tools: 6 public tools and 88 workspace tools. Each tool calls one API operation and returns what the API returns. Roles, validation and errors are the same as in the [B2B API reference](/reference/v1). Tools marked **destructive** ask for confirmation in clients that support it.

## Public (no credential)

Available on both `/mcp` and `/mcp/public`.

| Tool | Does |
| --- | --- |
| `public_events_list` | Search the catalog of published events |
| `public_events_get` | Event detail by slug |
| `public_events_availability` | Live stock and buyer prices per date and ticket type. Check it before creating an order. |
| `public_orders_create` | Create an order and return the payment link for the buyer |
| `public_orders_get` | Order status (`pending`, `paid`, `expired`, `cancelled`), plus tickets once paid |
| `public_tickets_resend` | Resend the ticket email to the buyer's original address |

Public ordering covers general admission tickets that are not members-only.

## Members area (enterprise)

`customer_me`, `customer_tickets`, `customer_ticket_get`, `customer_membership`, `customer_profile`, `customer_profile_update`, `customer_order_pending`, `customer_order_get`, `customer_order_release`, `customer_subscribe`, `customer_subscription_cancel`, `customer_ticket_cancel` and `customer_logout` act on behalf of a signed-in buyer. They require an enterprise service API key plus the buyer's session token. See [Credentials](/mcp/authentication#buyer-sessions).

## Platform staff

A separate set of `admin_*` tools manages the platform itself. They appear only for FreeTicket staff credentials and are not available to workspace accounts.

## Rendered results

In clients that support the MCP Apps extension, list and report tools render as a table or KPI tiles instead of raw JSON. The view is self-contained and makes no network requests. Other clients receive the same data as text.

## Global mode

Unless the connection is pinned to one workspace, list and row-based report tools read **every workspace you can access**. Their `workspace` argument narrows that:

- Leave it out, or pass `"all"`: every workspace you can access.
- `["id1", "id2"]`: only those workspaces. An id you can't reach comes back as an error for that id instead of being dropped silently.

Rows are tagged with `workspaceId` and `workspaceName`. Aggregated results carry no pagination cursor, so name one workspace to page deep. A workspace that fails is reported while the others still return. `reports_summary` returns KPIs for one workspace only, because KPIs can't be added up across workspaces.
